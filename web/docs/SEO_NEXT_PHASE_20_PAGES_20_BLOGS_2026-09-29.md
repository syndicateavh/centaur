### Why this phase is not 20 new page URLs

The old page list has material overlap with the current site. For example, it proposes separate URLs for India-wide course access, job-oriented finance training, six-week course information, guarantee terms, interview preparation, risk management, FinTech, and credit analysis even though the corresponding intent is already served by `/courses/`, `/india/`, `/placements/`, existing resources, or published blogs. It also proposes alternate regional paths such as `/india-bengaluru/`, while the site’s regional architecture uses nested paths such as `/india/bengaluru/`.

Creating every proposed URL would split authority, repeat content, and in some cases imply an additional course or local classroom that is not part of the published offer. Accordingly, this phase has **20 page work items**, not 20 new URLs. Source ownership review found that the two initial new-page candidates also belong on existing canonical pages; there are currently **zero justified new URLs** in this batch. The other actions improve or consolidate existing owners, are already covered, require business approval, or remain evidence-gated.

### Blog metadata and quality requirements

Use one intent owner per URL. Draft title tags around the actual query and brand; write a unique description that accurately summarizes the page, not a list of variants. Use the proposed slug only after checking the route registry, sitemap and keyword-owner map. Each article should answer the query early, include an original workflow/example or decision aid, show who reviewed regulated/current claims, cite authoritative sources close to the claim, and include relevant FAQs only when visible on-page.

Use `BlogPosting` plus breadcrumbs for blog URLs. Do not add FAQ schema merely to target rich results. Add contextual links to the specific module/career/resource owner in the relevant section, plus one appropriate conversion link; do not repeat exact-match anchors in every paragraph. A blog needs a real author/editor and subject-matter review—not a fabricated byline.

## Release order and acceptance gates

1. **Resolve ownership first:** register each of the 20 blog topics against the current route/keyword-owner maps; choose merge, expand or new only when distinct intent is established. The page batch currently has no justified new URL. Capture one primary query per canonical URL.
2. **Ship truthful page-owner work:** update `/courses/`, `/placements/`, `/india/` and the existing role/resource owners before adding new routes. Business-review all cohort, guarantee, fees, eligibility, local-access and placement claims.
3. **Reopen new-page candidates only after validation:** confirm distinct query intent with page-filtered Search Console and current India SERPs, then review overlap with existing canonicals. The BCom and Finance Operations Analyst intents currently map to existing pages and should not be split out.
4. **Publish blogs in topical groups:** (a) payment operations (#2, #13, #15–18), (b) investment operations (#3, #8, #20), (c) banking roles/risk (#4–6, #11–12, #14, #19), then the remaining topics. Regulatory/current topics require subject review before release.
5. **Technical acceptance:** visible H1 matches intent; unique title/description; self-canonical; `index,follow`; correct breadcrumb/schema; sitemap inclusion; no broken/orphan links; mobile layout and image alt text verified; internal links from at least one relevant hub and supporting page.
6. **Measure after deployment:** record production URL and date, inspect HTTP/canonical/robots/sitemap, then use Search Console URL Inspection and page/query reports. Track impressions, clicks, CTR, position, qualified enquiries and unqualified-query share. A sitemap submission is not proof of indexing or ranking.
