# Next 20 blog plan: SEO and editorial production

**Prepared:** 29 September 2026  
**Site:** Centaur Careers  
**Scope:** The next 20 blog candidates after the current published inventory review.

This is an editorial and SEO plan, not a claim that all 20 URLs should be created immediately. Every candidate needs a final India SERP review, a query-to-URL ownership check, and a source review before publication. If Search Console shows that an existing page already owns the intent, expand that canonical page instead of creating a competing URL.

## Strategy

The current site already covers broad accounting, reconciliation, KYC/AML, UPI, settlement, investment-banking, and finance-career topics. The next batch should therefore target narrower workflows, comparisons, and practical decision aids. This creates useful long-tail coverage without producing another generic definition article for an existing owner.

Do not assign search volume or keyword difficulty from an unverified export. Validate each primary query in Google India and Search Console, record the result in the content ledger, and only then approve the final title and URL.

## Draft metadata rules for every article

Each approved article should receive:

- One `seo.focusKeyword` matching the final query owner and 3–6 genuinely close `seo.secondaryKeywords`.
- A unique title tag, normally 50–60 characters before the brand suffix where possible, and a unique 140–160 character description written as a benefit-led answer. Do not list every synonym in metadata.
- A self-referencing canonical, `index,follow`, truthful `datePublished`, a maintained `dateModified`, a truthful author/editor, and a visible update date when the article contains changeable facts.
- A visible H1 that matches the intent, an answer-first introduction, 6–8 useful H2 sections, one original fictional workflow/example or decision aid, and at least 1,500 substantive words where the topic warrants it. Shorter articles must be justified by the SERP intent rather than a word-count target.
- 3–5 human-readable tags from the row above. Tags are topical signals rendered on the article; do not create thin indexable tag archive pages.
- One original image at approximately 1672×941 WebP under `public/images/blog/`, with a unique safe filename, descriptive alt text, and an image concept that supports the article. Do not reuse a cover image across this batch.
- `BlogPosting` and `BreadcrumbList` structured data that describe visible content. Use FAQ schema only if visible FAQ content and the project’s schema rules support it; never add it only to seek a rich result.
- 5–8 contextual internal links: at least one relevant hub/resource, one related article, and one appropriate next-step or course link. Use varied, descriptive anchors and do not force an enrolment CTA into an answer that is purely informational.

## Source and review gates

- **All 20:** run an India SERP review, check Search Console query ownership, inspect existing canonical overlap, and record the decision in the editorial ledger.
- **Current or regulated topics (#10, #12, #14, #15, #18):** cite current primary sources, write an “as reviewed” date, and obtain a subject-matter review before publication. RBI’s KYC materials are amended over time, and RBI’s own FAQ distinguishes banks from NBFCs; neither topic should be written from an undated third-party summary. [RBI KYC amendment](https://www.rbi.org.in/scripts/NotificationUser.aspx?Id=12866), [RBI KYC Master Direction](https://www.rbi.org.in/commonman/Upload/English/Notification/PDFs/MD18KYCF6E92C82E1E1419D87323E3869BC9F13.pdf), [RBI NBFC FAQ](https://www.rbi.org.in/scripts/FAQView.aspx?Id=3).
- **Payments (#7–10):** validate the current rail, status, settlement, dispute and timing language against RBI/NPCI documentation at writing time. The current UPI ecosystem includes product-specific flows, so the article must not treat one product page as a universal rule. [NPCI UPI product reference](https://www.npci.org.in/product/upi-global-acceptance).
- **Examples:** use invented values and explicitly label them fictional. Never include customer, account, card, KYC, transaction or employer data.
- **Commercial claims:** do not add fees, salaries, placement outcomes, employer names, delivery promises, locations, guarantees or course claims unless they are approved and already supported by the canonical business page.

## Indexability acceptance checklist

Before release, verify the rendered production URL—not just the JSON record:

1. The article is linked from `/blog/`, its category page, and at least one relevant existing page.
2. The route is included in the canonical route registry and sitemap, with no query-string or duplicate-slug variant.
3. Rendered HTML contains one H1, unique title/description, self-canonical, `index,follow`, Open Graph/Twitter metadata, image alt text, `BlogPosting`, and breadcrumbs.
4. The article has no orphan links, broken internal links, placeholder copy, repeated image, duplicate metadata, or unsupported claims.
5. Run the blog, build, structured-data, internal-link, sitemap, and technical-SEO checks; then use Search Console URL Inspection after deployment.

## Measurement

Track each URL from its publication date at 28 and 90 days: indexed status, impressions, clicks, CTR, average position, non-brand query share, internal clicks to related pages, engaged sessions, and qualified enquiries. A sitemap entry or a URL Inspection request is not proof of indexing or ranking. Refresh, consolidate, or retire a topic when query ownership or user behavior shows that it is not serving a distinct need.
